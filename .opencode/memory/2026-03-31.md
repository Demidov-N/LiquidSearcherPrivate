## Retrieval Evaluation Correction

We identified a methodology mismatch in Block 4 retrieval scoring.

**What the current evaluation was doing:**
- Ground truth ordering was based on global `LiquidityScore` / liquidity-distance labels.
- This measures whether rankers align with liquidity similarity or liquidity level.

**What the intended product objective actually is:**
- Find stocks that are similar to the query in behavior/characteristics.
- Then prefer candidates that are more liquidity-efficient than the query.

**Why this matters:**
- The current score partially inverts the desired objective by rewarding liquidity similarity itself.
- The model should remain liquidity-agnostic in first-stage retrieval.
- Liquidity should mainly enter in reranking / constrained utility metrics.

**Conclusion:**
- Need a revised spec for score adjustment.
- Future metrics should evaluate "similar + liquidity improvement" rather than pure liquidity reference ordering.
